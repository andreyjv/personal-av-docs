What's new in ALMS in 2017

:::note Edition alms · imported from live Hugo on 2026-10-07. Guides stay latest. Original page. :::

What's new in ALMS in 2017 We were a little behind in providing new content for the “What’s New” section this year. That’s not to say there we weren’t busy improving ALMS, just that we didn’t get to providing regular updates. This entry provides an update on some of the enhancements made over the second half of 2017. New Alert Widgets We added a series of new widgets focused on Alerting: Alert List Widget This widget shows the Alerts from your account as a list. It is available both for the fleet or for a specific system. You can filter the alerts to be shown by rule or limit the display to alerts that are still ongoing. From this widget, you can: Click on the system name to show all alerts for a system (available only for fleet version on the start page dashboard); Click on the alert name to show all systems with the same alert; Click on a link to go to the system details to investigate deeper; Show a popup with the alert duration when hovering the start or end date of the alert. Alert History Widget This widget shows the recent history of the system’s alerts on a graphical view. You can browse the alert history within a given period, zoom on a given date and hide alerts in the graph by clicking on the bottom legend. This widget is only available in the System Detail dashboard. Alert Configuration In the on-going effort to improve alerting, we made a series of enhancements to extend actions when an alert is triggered. New actions include: Call a Callback URL When creating or editing an alert rule, you can specify one or more URLs that will be called every time the alert is raised. Those webhooks permit to inform a third party application about the alert raised in AirVantage. Webhook is a stateless mechanism and messages are sent in JSON format with the content-type “application/json”. Messages sent to an unreachable endpoint will be lost. Send Command This action sends a command to the system which raised the alert. The command will be get by the system in the next device’s communication with ALMS. You can define one or more Send a Command actions. This sends a command to the device when an alert is raised, and requires an AAF application to operate. Please note that this feature does not work with ALEOS firmware at this time. Apply Label You can apply a label on systems that have raised an alert on a specific rule. The label will be automatically removed when the alert will be cleared. This can be used for example to identify from the grid all systems being on alert on a specific rule. Apply Setting This action applies a pre defined template to the system which raised the alert in order to configure your machine according to the context (initialization, local user action, new local status, issue detected). This template will be applied in the next device’s communication with AirVantage. You can only define a single Apply Settings. Print Button A “print” button has been added to the Start Page (Dashboard), Monitor -> Systems, and Device pages, allowing you to print those pages. Enhancement to the Apply Settings Workflow Accessed from the action buttons on the Monitor -> Systems page, the Apply Settings feature allows the user to update settings (e.g. update ACEmanager Password) with the same value or unique values, on multiple systems. This feature has been enhanced to improve the workflow. Added Fields to Export Data A number of missing fields were added to the Export Data feature. Support for IKE v2 on the ALMS VPN Earlier this year, we updated the ALMS VPN to add support for IKE v2. New ALMS VPN implementations will use the updated standard, and existing customers may request to have their ALMS VPN updated.
